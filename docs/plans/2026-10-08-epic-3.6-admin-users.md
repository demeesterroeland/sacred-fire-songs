# Implementation Plan: Epic 3.6 Administrative Management & Story 3.6.1 User Overview

**Epic:** #257 - [Epic 3.6] Administrative Management: Configuration, Users, Settings & Songs  
**Story:** #258 - [Story 3.6.1] As an Admin, I want to have an overview of all users, view their details, and see their contributions  
**Branch:** `feat/userstory-3.6`  
**Worktree:** `.worktrees/feat-userstory-3.6`  
**Date:** 2026-10-08  

---

## 1. Goal

Provide administrators with a dedicated administrative view to inspect all registered users, examine their profile metadata (roles, musician setting, contact info, join date), and review their contributions (songs created, versions submitted, public playlists created, recordings). Enforce strict server-side and database-level role security so only users with `role = 'admin'` can access administrative endpoints.

---

## 2. Acceptance Criteria (Story 3.6.1)

```gherkin
Scenario: View user list overview
  Given I am logged in as an Admin
  When I navigate to the Admin Users overview page (/admin/users)
  Then I should see a list of all registered users
  And for each user I should see summary details (e.g., name/email, role, join date, status)

Scenario: View user detail and contributions
  Given I am logged in as an Admin
  And I am viewing the users overview list
  When I select a user to view their details
  Then I should see their profile details (e.g., email, role, musician status, last active)
  And I should see an overview of their contributions (e.g., songs added, versions submitted, public playlists created, comments/flags)

Scenario: Non-admin access restricted
  Given I am logged in as a Member or Gatekeeper
  When I attempt to access the Admin Users overview page
  Then I should be denied access with an unauthorized notice
```

## 3. Architecture & Data Strategy

### 3.1 Database & Row-Level Security
- In `profiles`, RLS currently allows: `Users can read own profile` (`USING (id = auth.uid())`).
- We will add an RLS policy for Admins:
  ```sql
  CREATE POLICY "Admins can read all profiles"
  ON profiles FOR SELECT
  TO authenticated
  USING (
    (SELECT role FROM profiles WHERE id = auth.uid()) = 'admin'
  );
  ```
- Update `docs/design/db-schema.sql` to maintain sync.

### 3.2 Server-Side Data Fetching (`lib/admin/serverQueries.ts`)
- `getAdminUsersList()`: Fetches all profiles with aggregated counts:
  - `compositions_count`: Count of songs where `owner_id = profile.id`
  - `versions_count`: Count of song versions where `contributor_id = profile.id`
  - `playlists_count`: Count of playlists where `owner_id = profile.id`
- `getAdminUserDetails(userId)`: Fetches a single user's detailed profile along with:
  - List of songs created (`compositions`)
  - List of song versions (`song_versions`)
  - List of playlists created (`setlists`)

### 3.3 Admin Access Protection
- `app/admin/layout.tsx`:
  - Validates authentication via `createClient()` server client.
  - Queries user's profile to verify `profile.role === 'admin'`.
  - If unauthenticated, redirects to `/auth/login?next=/admin/users`.
  - If logged in but not admin (`member`, `gatekeeper`, `musician`), renders an **Access Denied** notice with return home button.

### 3.4 Navigation Integration
- In `components/common/navigation/UserProfile.tsx`:
  - When `user.role === 'admin'`, show an **Admin Panel** link (with a Shield icon `ShieldCheck`) linking to `/admin/users`.
- In `app/admin/layout.tsx`:
  - Provide a clean administrative sub-navigation header (e.g., "Users", "Songs", "Settings") laying the foundation for future stories in Epic 3.6.
