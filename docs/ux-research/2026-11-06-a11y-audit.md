## Status in one paragraph

The **automated** part is done: axe-core finds no violation of any impact on the song page, the Practice panel (Listen and Record), the recorder and the sheets and dialogs reachable from them, and keyboard journeys prove that dialogs keep focus and give it back. The **manual** part is **still to be done**: nobody has used the song page with VoiceOver (iPhone) or TalkBack (Android) yet, because the agent that did this work cannot run them. Section 5 is the checklist for that pass; its result column is empty on purpose. Automated checks find roughly a third of accessibility problems (names, roles, contrast, structure); they cannot judge reading order, wording or whether an announcement comes at the right moment.

## 3. Findings the tool does not report, and what was done

| Finding | Fix |
| :--- | :--- |
| The Practice panel was not a dialog: no role, no name, no Escape, Tab left it, focus was lost on close. | `role="dialog"`, `aria-modal`, name *Practice <song>*, `inert` while closed; `useModalFocus` moves focus in, wraps Tab and Shift+Tab, closes on Escape and returns focus to the opener (UXA-050). |
| Listen and Record were two plain buttons with a colour as the only selected state. | ARIA tabs: `tablist`, `tab`, `tabpanel`, `aria-selected`, arrow keys, Home, End, roving tab stop. The underline stays as the visible cue. |
| The song menu (⋯) was a hand-built overlay: no dialog, no focus handling. | Now the shared `BottomSheet` (UXA-052). |
| A controlled `BottomSheet` (the take actions sheet) did not return focus to the *More actions* button. | `BottomSheet` remembers the opener and refocuses it on close. |
| The recorder's file upload was a clickable `div`: unreachable with a keyboard. | A real button; the hidden file input is out of the Tab order. |
| Recorder state changes (*Recording...*, *Recording paused*) were silent. | The state line is a `role="status"` live region. |
| The desktop Practice button's equalizer animated even with reduced motion on. | `motion-safe:` on the animation; static bars otherwise. |
| The Practice close button was a 32 px target. | 44 px (`size-tap`). |
| The delete confirmation was a hand-built overlay outside the Practice panel's focus scope: no dialog role, took no focus, Tab never reached Cancel or *Yes, Delete*, and Escape closed the panel underneath. | `DeleteConfirmationModal` is now a Radix alert dialog (role `alertdialog`, name = title, description = message): focus starts on Cancel, Tab is trapped, Escape closes only the confirmation, focus returns to the opener (or to the Practice panel when the deleted take's button is gone), and the panel behind is hidden from assistive technology. The playlist, song and songs-list delete confirmations use the same component. |
| Escape while renaming a take, or while a take is being moved with the keyboard, also closed the Practice panel. | The rename field marks the key as handled (`preventDefault`), which the panel's Escape handler respects. The other widget in the panel that uses Escape is the take list's drag and drop (Escape cancels a keyboard drag): dnd-kit attaches its listener after the panel's, so `preventDefault` is not visible yet; the panel is told a drag is active (`escapeBusy` option of `useModalFocus`) and ignores that Escape. The next Escape closes the panel. |
| The Tab trap skipped `iframe`s: on Listen as a member the provider button is last, so Tab wrapped to Close and the visible player was never reached. | `iframe` joins the tabbable list in `lib/a11y/focusTrap.ts` (not when `tabindex="-1"`). Keys pressed inside a third-party player do not reach the page, so `useModalFocus` also listens for `focusin`: focus that lands outside the panel (Tab leaving the player, or coming back from the browser toolbar) is pulled back in, to the first or last control depending on the direction, unless a Radix layer is open. |

## 4. Keyboard and focus review

Playwright journeys (`keyboard and screen reader behaviour` in the same spec) check, on a phone with a keyboard attached:

- Practice opens with Enter; it is a modal dialog named after the song; Tab and Shift+Tab (14 presses each way) never leave it; Escape and the close button close it and focus is back on **Practice**.
- The take actions sheet, the playlist sheet and the song menu return focus to the control that opened them after Escape. After the Make public dialog closes, focus is on the take's *More actions* button, inside the Practice panel.
- Listen and Record: arrow keys, Home and End move between the tabs and select them; only the selected tab is a tab stop.
- The recorder announces *Ready to record*, *Recording...*, *Recording paused* and back; while recording, every button in the panel has an accessible name.
- The file upload can be focused and opened with Enter.
- Reordering takes: Space picks a take up, an arrow key moves it, Escape cancels the move and the panel stays open; the next Escape closes it.
- Dialogs opened from a take (Make public, Share, Singer Attribution), the song menu's Delete confirmation: Escape closes only the dialog and focus returns to the take's *More actions* button, or to ⋯.
- Delete confirmations return focus to the control that opened them when that control still exists; otherwise to a named fallback: the song ⋯ button (song page), the menu button (playlist menu), the first song left in the list (songs list), the Practice panel (a deleted take). Where the caller names none, focus is left to the browser.
- The heart is a toggle button (`aria-pressed`).
- Delete take: the confirmation opens with focus on Cancel; Tab and Shift+Tab cycle between Cancel and *Yes, Delete*; Escape closes only the confirmation (the Practice panel stays, the take is kept) and focus is back on the take's *More actions* button; Cancel and a tap on the backdrop keep the take.
- Renaming a take: Escape ends the edit without closing the Practice panel.
- Listen with a reference video: Tab goes past the last control on to the embedded player (it used to wrap to Close), and once focus has left the player it is back in the panel within a few presses. A player that cannot load (no network) has nothing to focus, so there focus passes straight through it.
- Practice: the backdrop closes it and focus is back on **Practice**.

Not covered by the automated journeys: Tab order of the take rows with the drag handle, what happens **inside** the YouTube, Spotify and SoundCloud players (third-party iframes: the page can see that Tab reaches the player and where focus lands when it leaves, not the keys pressed inside it), actually confirming a delete (it would remove the fixture), the mini player while the panel is open (its controls follow the panel's in the Tab order by design, UXA-050).

## 6. Left open

- The mini player floats above the Practice panel; with `aria-modal` a screen reader reads only the panel. The same play controls are on each take row. Check this in step 4 and 6 of the manual pass.
- `SearchSuggestions` uses fixed element ids; with two search panels open at once on the same page the ids would repeat. axe did not flag it on the song page, so it was left alone.
- Pages outside the song page and the Practice panel (Home, Songs, Library, playlists, Add Song, admin) were not audited here. The `Songs`, `Add Song` and edit pages also nest a second `main` inside the layout's, like the song page did.
- The desktop layout and the musician and admin roles were not run.
